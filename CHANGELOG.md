# Changelog

This file lists every change that affects a workflow referencing these actions. CI, documentation and test-only changes are
left to the git history. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and releases use
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Every release has an immutable tag (for example `3.0.3`). Each major line also has a floating tag (for example `v3`) that
moves to the newest release in that line, so a workflow pinned to `@v3` picks up every 3.x entry below automatically.

## 3.x

### Upgrading from 2.x

Work through this table before changing a reference from `@v2` to `@v3`. GitHub Actions only *warns* on an input a
composite action does not declare, so a renamed or removed input that is still passed is silently ignored.

| Change | Affects | What to do |
| :--- | :--- | :--- |
| Four Java inputs renamed to match `actions/setup-java` v6: `java-jdkFile` → `java-jdk-file`, `java-server-username` → `java-server-username-env-var`, `java-server-password` → `java-server-password-env-var`, `java-gpg-passphrase` → `java-gpg-passphrase-env-var` | `setup` | Rename the inputs in your workflow. |
| Elasticsearch replaced by OpenSearch: `elasticsearch-version` and `elasticsearch-plugins` are removed, `opensearch-version` and `opensearch-plugins` are added | `setup` | Move to the OpenSearch inputs and choose an OpenSearch version. This is an engine change, not a rename, so an Elasticsearch version such as `8.11.0` is not valid. If you keep the old inputs, no search service starts (`opensearch-version` defaults to `none`) and tests that need one fail. |
| Git credentials are no longer persisted. In 2.x the checkout inside `setup` always kept the token in `.git/config`. The new `persist-credentials` input defaults to `'false'` | `setup` | Set `persist-credentials: 'true'` if a later step in the job runs an authenticated `git push` or `git fetch` against `origin`. |
| Review comments are posted with the new `reviewdog-token` input (default `${{ github.token }}`) instead of `github-token` | `linters/actionlint`, `eslint`, `flake8`, `golangci`, `hadolint`, `ktlint`, `markdownlint`, `pmd`, `protolint`, `rubocop`, `shellcheck`, `swiftlint`, `yamllint` | Give the job `permissions: pull-requests: write`, or pass `reviewdog-token` explicitly. If the job token is read-only, the linter still passes or fails correctly, but inline review comments stop appearing. |
| Empty required inputs now fail the step. An unset or misspelled secret used to arrive as an empty string, run nothing and report success | `aws`, `codedeploy/deploy`, `codedeploy/s3copy` | Fix the input or secret named in the `required input(s) empty` error. |
| `flake8-docstrings` is installed, so pydocstyle `D*` codes are now reported | `linters/flake8` | Fix the new findings or add their codes to `ignore` in `.flake8`. The `.flake8` generated by github-build already ignores the missing-docstring family (`D100`–`D107`). |

### [3.0.3] - 2026-09-10

No changes to the actions.

### [3.0.2] - 2026-09-02

#### Fixed

- `linters/shellcheck`: the exclude list is passed newline-separated, so the vendored directories (`vendor`,
  `node_modules`, `Pods`, ...) and `*.bats` files it names are actually skipped. Earlier releases passed it
  colon-separated, which the underlying action did not apply.

### [3.0.1] - 2026-09-02

#### Changed

- `linters/shellcheck`: also lints extensionless files that start with a shell shebang, and skips `*.bats` files. Scripts
  that were never checked before can now produce findings.

### [3.0.0] - 2026-08-31

See [Upgrading from 2.x](#upgrading-from-2x) for the breaking changes in this release.

#### Added

- `setup`: `persist-credentials`, `opensearch-version` and `opensearch-plugins`.
- `setup`: the new `actions/setup-java` v6 inputs `java-force-download`, `java-set-default`, `java-verify-signature`,
  `java-verify-signature-public-key`, `java-mvn-server-credentials`, `java-mvn-repositories`,
  `java-mvn-repositories-include-central`, `java-mvn-repositories-prioritize-central`, `java-cache-jdk`, `java-cache-path`,
  `java-cache-read-only`, `java-show-download-progress` and `java-problem-matcher`.
- `reviewdog-token` on the 13 reviewdog linters listed in the upgrade table.

#### Changed

- `setup`: git credentials are no longer persisted by default.
- The 13 reviewdog linters post review comments with `reviewdog-token` instead of `github-token`.
- `aws`, `codedeploy/deploy` and `codedeploy/s3copy`: validate required inputs and fail when any is empty.
- `linters/flake8`: installs `flake8-docstrings`.
- `linters/phpstan`: the composer GitHub token is passed through `COMPOSER_AUTH` on the install step. It is no longer
  written to the global `auth.json`, so later steps in the job do not inherit it.
- `soup`: the tool location is a step output and no longer exported to the job environment as `soup_location`.

#### Removed

- `setup`: `elasticsearch-version` and `elasticsearch-plugins`, replaced by the OpenSearch inputs.
- `setup`: `java-jdkFile`, `java-server-username`, `java-server-password` and `java-gpg-passphrase`, renamed as listed in
  the upgrade table.
